# 工程经验

## 2026-10-06：桌面 Agent 执行作用域与验收修复

- 目标：按用户确认的桌面端定位修复审查问题，并验证实际行为。
- 踩坑：绑定后台模型时直接使用原始依赖会绕过引擎的关闭信号；测试中同步抛出的 abort 也需要由 async 回调接入拒绝断言。
- 解决：绑定工厂接收引擎受控的模型端口，保留模型快照、归属和取消信号；以真实 Turn 生命周期回归验证。
- 踩坑：旧 PDF fixture 只有魔数/文本片段或成功标记，无法覆盖新的实际 parser/renderer 验收。
- 解决：构造真正有效的 PDF 和渲染图；宿主解析生成身份绑定的回执，保留任务完成/恢复断言，并独立测试标记和伪造回执的反例。
- 约定：局部读取、默认目录和无用户的全局工具 metadata 均不能替代明确任务的验证与作用域。
- 踩坑：模型选择/恢复 fixture 使用 1 秒租约，冷启动计时也混入关闭性能断言，低资源并发时产生误失败。
- 解决：选择与恢复用例使用生产租约；进程杀死后只过期该隔离数据库中精确 owner/fencing 的旧租约。关闭与流释放的功能时限仍单独严格断言，未知请求仍禁止重放。
- 踩坑：全量排序断言依赖真实 50ms 时钟，CPU 调度导致 coverage 正确降为 partial。
- 解决：排序用确定性时钟，另以注入时钟验证时间限制仍生效；不调整生产护栏。
- 交付：全量扫描及原失败批次整批复验闭环，保留失败历史；不将模拟验证写成真实模型或 Windows 安装结果。

## 2026-10-07：模型设置页接入模型知识库（客户端）

- 目标：模型设置页读取 `/api/model/catalog`（models.dev 知识库），且没有预设的供应商也能通过自定义路径配置。
- 踩坑：`ProviderEditor` 通过 `createPortal` 挂载，而 `capturePanel` 的兜底目标是 `document.body`——它不在 React 根容器内。受控 input 在根容器外时，React 委托监听收不到事件，jsdom 里 `setInputValue` 便永远改不了组件状态（真实 Electron 里同样会丢输入）。
- 解决：兜底改为 `node.parentElement`（面板自身所在容器），编辑器始终留在拥有它的 React 根内；新增输入控件沿用仓库既有的 `onInput` 写法，不依赖 `onChange` 的 value tracker 注册。
- 踩坑：用 PowerShell `-replace` + `Set-Content` 改源码时把 `Get-Content` 的输入文件写成了输出路径，覆盖了 `ProviderEditor.jsx`。
- 解决：`git checkout --` 恢复后改用局部 edit 工具重放改动，并立刻用 `git diff --stat` 核对；此后不再用字符串替换改源文件。
- 约定：批量“加入全部”是合并语义（会重新加回手工删掉的 id），所以只把当前缺失的 id 交给纯函数，并在文档注释里写明这一点，不用断言掩盖。

## 2026-10-13：二次审查修复与边界回归

- 目标：修复只读文档误熔断、删除假成功、输入法误提交、窄屏挤压和部分缓存计数误判，不放宽授权或 Office 输出安全策略。
- 踩坑：输入 DOCX 的输出格式警告被按生成失败累计；仅检查“任务需要文件”仍会误伤需要阅读源文档的任务。
- 解决：把熔断限定为请求中的生成器或真实 mutation debt 对应路径；真实 Office 读取回归同时覆盖纯只读任务和有输出要求但源文件未修改的任务。
- 踩坑：行内输入忽略 composition Enter 后，Escape 仍可能冒泡到菜单并导致 blur 提交。
- 解决：共享 composition 判断，并保护输入与菜单的组合按键；普通 Enter、Escape 和组合结束后的提交仍分别验证。
- 踩坑：把面板切换为 Portal 模态会重新挂载工具树，丢失草稿并可能重建终端连接。
- 解决：同一个挂载树只切换布局样式，复用焦点/背景隔离 hook；以输入节点身份和草稿跨窄/宽模式保持的行为断言钉住。
- 踩坑：jsdom 测试使用无作用域的 `.left-rail-action` 会点到“最近”栏的新建按钮，得到夹具错误而不是删除行为失败；直接比较不同 DOM 节点也可能生成巨大错误诊断。
- 解决：限定到 session row，确认到达 DELETE；节点身份用布尔断言，避免打印整个 DOM 树。
- 验证：10 个定向文件 57 项通过，离线评测 71 项通过，lint/debt/i18n/依赖/类型/复杂度/构建通过；隔离浏览器复验布局、输入法和删除拒绝后重试。
- 全量历史：1142 文件首次扫描记录两个失败；旧布局源码断言更新后原 100 文件批次复验通过，移动页 i18n 夹具单独重跑通过但首次失败原因未完全定位。保留原始 FAIL，不改写成当时全绿。
- 约定：等待删除可收起窗口，但不取消已发送的服务端操作；失败或结果未知只说“未能确认”，不假称已删除或确定未删除。

## 2026-10-14：本机免登录、观测与桌面体验收敛

- 目标：按用户授权先制定计划再实施；默认本机无需注册/登录，同时保留身份归属、回环边界、目录授权与工具审批。
- 修复：策略拒绝计数以独立版本保存到检查点，并用调用 ID 防止恢复重复计数；本机未知/连接失败状态不得误入多人登录流程。
- 修复：删除状态按会话和操作 token 隔离；旧布尔结果兼容，通过操作级 observer 传递公开错误码。observer 不是执行权威，抛错不能改变实际 mutation 结果。
- 统计：缓存读写分别观测；覆盖率与上报样本命中率分开，无费率返回 null；不能凭默认五分钟 TTL 或计数重叠断言过期、内容变化或计费事实。
- 观测：宿主进展/公开输出时间随原 fenced action 合并，不多提交一次游标，不把宿主时间当浏览器首帧或私有推理。输入框诊断 Escape 不得取消正在进行的请求。
- 性能：不可变 React 快照只缓存数字，WeakMap 不额外保存正文；这不是 PromptCompiler 或模型 KV 缓存。历史消息 memo、大列表分页和折叠不构造隐藏行树分别有行为回归。
- 踩坑：部分旧源码断言把单行标题、无空项目、旧 action 形状当成产品契约；保留字号/权限/游标等真实要求，更新为新契约，并用组件/浏览器行为补证，不删断言消红。
- 踩坑：移动页混合测试模块图、未消费 mainAs 的布局替身和固定短等待掩盖了真实挂载路径；全量又观察到数据仍在 loading 时断言。
- 解决：使用统一 JSX 图和真实 AppProvider/Router/I18n/页面，显式 Node tick 按可观察条件等待数据，不固定 sleep；双语连续五轮及全量通过。
- 踩坑：直接断言 DOM 对象与 null 不相等时，失败诊断可能展开巨大 React/DOM 图导致 V8 内存错误。用布尔身份/存在性断言保持真实验证，避免打印整棵树。
- 现场：局部 edit 会归一化混合 CRLF/LF 文件；先确认归一化后的业务内容仅有预期修改，再恢复工具引入的 EOL 噪声。不得靠 checkout/reset 覆盖现场，也不修改用户 Git 配置掩盖空白问题。
- 验证：新的从头全量 1151 文件 PASS，离线 71 项，所有门禁与构建通过；完整旧 FAIL 保留。2000 消息/60 工具/30 更新的离线估算结果一致，中位数 13.900ms→0.108ms；不当作 UI FPS 或真实模型性能。
- 验收：自有 loopback 假模型驱动真实 Gugo 请求/事件/UI，未用真实密钥或外部额度；真实 Provider 基准和完整 Electron 安装包验收仍需显式开展。

## 2026-10-14：账本、并发与 Web 后续批次

- 用户确认修复计划，Electron/原生能力不纳入本轮；本机免登录、安全与数据归属保持。
- 累计快照不是增量：同 Turn 的暂停 500、完成 800 不能相加成 1300；日期范围按范围内已记录响应统计，累计另列。缺计数不抹掉已知观测，相等数字不代表重复请求。
- 来源沿实际物理尝试记录：同名 Provider/端点/配置不能混成一个缓存连续性，默认配置不能代表 failover 后的真实来源。
- 名称操作必须同时控制客户端顺序和存储版本，忽略旧回包不能保证后端最后名称正确。未知写入不自动重放；身份/数据源变化后旧回调不得提交。
- 编译观测从本次返回块取得，不能用并发进程全局计数差值归因；同轮复用、检查点复用不冒充新缓存命中。
- 踩坑：只在即时消息保存诊断不够，水合会丢掉上一轮参考。修复宿主状态/检查点/消息 modelContext 以及真实 snapshot normalizer，白名单 schema 丢弃非法和额外敏感字段。
- 踩坑：浏览器绘制采样最初使用了不存在的 markdown 类；沿真实 DOM 校正选择器。双 RAF 是绘制机会，不是 OS 呈现；遮挡/后台/缺少起点保持未知。
- 性能：排序比较中不要重复解析相同时间戳；预计算保持顺序一致。5000 会话局部 median 56.675ms→3.511ms，不当作全应用 FPS。
- 门禁：组件超出 300 行时提取职责，不调高预算；源码重命名断言更新为协调 Hook 并由真实浏览器/SQLite 和并发用例补证。
- 验证：15 文件/71 项关键回归、5 文件/210 项恢复与协议回归、离线 71 项通过；最终新的从头全量 1157 文件 PASS、退出码 0。不是重跑拼接；以新报告为准。前两轮停止原因、首次 UI 冷启动/脚本同步失败均保留。
- 新真实评测数据集有 3 个隔离任务和外部判定器；只验证夹具/参考实现不构成真实模型成功率，未使用用户密钥或额度。

## 工程治理：验收、窄端口与工作树证据

- 当前状态只进入 docs/CURRENT_STATE.md；契约和债务各留单一权威位置，不继续把日期报告当当前规范。
- 目标契约必须区别执行成功、检查通过、修改覆盖、目标满足；明确 command/cwd、最终文件摘要、人工与 artifact 身份，不把模型自称完成当证据。
- 自定义包检查既要归一验证 kind，也要保持完整脚本的 family/scope；普通和命名空间脚本不能互相清除失败。
- Tool schema 的 pattern 先遵守现有安全正则子集，再在执行端做完整命名校验；不能使用传输层不支持的复杂 pattern 导致工具无法执行。
- 窄阶段要连生产 consumer 做严格检查；只声明 readonly fixture 或只校验 241 项袋都不能算阶段隔离完成。
- 迁移源码回调断言时，必须用生产 Hook/真实组件行为接替；首次全量仍发现另一文件复制同一回调断言，已补迁移并保留失败日志。
- 工作树盘点分组不等于原子提交；隔离 archive 上只叠加产物组已定向验证，其余共享文件仍需逐 hunk 闭包审查。未授权不操作原 index/commit/push。

## 2026-10-14：上下文圆圈口径

- 用户反馈圆圈不真实；真实 Hook 隔离复现证实草稿/附件未入参，上次实际输入一直压住当前估算，切模型只换分母。
- 当前占用与最近请求输入、累计消耗必须分开；发送前只能是估算，不把缓存命中当作释放上下文。未知窗口不显示确定百分比，未计量附件不按零计。
- 圆圈和浮层共享 resolver；加入草稿、附件与后续输出，保留上游实测零值作为历史参考，不钉住当前占用。
- 服务端复用现有组包与保留对话发布数值观测，按请求/模型/来源/配置关联；校准值仍为估算。不额外读文件、编译提示词、回忆记忆或调用模型。
- 关键踩坑：processModelResult 会清理 modelInvocation；最终保留观测应继承已校验的完成观测，不能延长句柄或改重放策略。已补句柄清理后的回归与实际浏览器验证。
- UI 新鲜度摘要只用于显示，不是安全/执行权威；消息或工具配置改变后作废旧基准，旧记录缺信息保持未知。
- 定向 11 文件/244 项、补充 6 文件/23 项及离线 71 项通过；新的从头完整全量 1161 文件 PASS、退出码 0。验收见 docs/CONTEXT_METER_2026-10-14.md。
