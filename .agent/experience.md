# 工程经验

## 2026-10-06：桌面 Agent 执行作用域与验收修复

- 目标：按用户确认的桌面端定位修复审查问题，并验证实际行为。
- 踩坑：绑定后台模型时直接使用原始依赖会绕过引擎的关闭信号；测试中同步抛出的 abort 也需要由 async 回调接入拒绝断言。
- 解决：绑定工厂接收引擎受控的模型端口，保留模型快照、归属和取消信号；以真实 Turn 生命周期回归验证。
- 踩坑：旧 PDF fixture 只有魔数/文本片段或成功标记，无法覆盖新的实际 parser/renderer 验收。
- 解决：构造真正有效的 PDF 和渲染图；宿主解析生成身份绑定的回执，保留任务完成/恢复断言，并独立测试标记和伪造回执的反例。
- 约定：局部读取、默认目录和无用户的全局工具 metadata 均不能替代明确任务的验证与作用域。
- 踩坑：模型选择/恢复 fixture 使用 1 秒租约，冷启动计时也混入关闭性能断言，低资源并发时产生误失败。
- 解决：选择与恢复用例使用生产租约；进程杀死后只过期该隔离数据库中精确 owner/fencing 的旧租约。关闭与流释放的功能时限仍单独严格断言，未知请求仍禁止重放。
- 踩坑：全量排序断言依赖真实 50ms 时钟，CPU 调度导致 coverage 正确降为 partial。
- 解决：排序用确定性时钟，另以注入时钟验证时间限制仍生效；不调整生产护栏。
- 交付：全量扫描及原失败批次整批复验闭环，保留失败历史；不将模拟验证写成真实模型或 Windows 安装结果。
