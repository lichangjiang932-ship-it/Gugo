# 输入框上下文圆圈：口径与新鲜度修复

2026-10-14。用户反馈圆圈不像真实上下文，已确认计划后实现。默认本机免登录、工具权限、目录授权和模型调用策略保持。

## 1. 复现与根因

真实前端 Hook 的隔离 SSR 复现：空草稿显示 800；加入大量中文与附件仍显示 800；切换另一个模型后仍显示 800，只换分母。旧 Hook 没有接收输入/附件/模型身份；组件优先选择最近助手消息 actualPromptTokens，使历史请求输入压过当前估算。

上游输入 Tokens 是那一次请求的报告，不是“当前待发送上下文”。不能把累计消耗、缓存命中或最近一次输入直接当作当前窗口占用。

基线 3 文件、24 项通过，但没有覆盖这些变化，已补场景。

## 2. 统一计量

新增 `src/lib/contextMeter.js`：

- 圆圈与弹层使用同一 meter，不再各写 actual → server estimate → local estimate 的优先级。
- 默认明确为“待发送上下文（估算）”，加入当前草稿与可见文本附件；已产生的助手回复、工具结果随消息更新计入。
- 最近上游输入或服务端输入估算另列为历史参考；显式零保留，不等于当前占用为零。
- 已缓存内容仍占上下文，不减 cacheHitTokens，也不把累计消耗当窗口占用。
- 无有效窗口不显示确定百分比；小于 1% 保留细分，不再用最少 4% 的弧长放大读数。
- 附件正文未知、图片计量不确定或已截断时标注未完整计量，不以文件大小或零 Token 冒充精确输入。

本地分项仍是可见内容估算，不强行凑成服务端校准总量；UI 明确说明这一区别。

## 3. 服务端关联与校准

新白名单 `modelContextUsage` 观测包含请求/物理尝试身份、实际与配置模型/来源、配置版本、有效窗口、输入估算、上游输入以及保留上下文估算，只含标量，无请求正文、工具结果、凭据或私有推理。

- 准备观测取现有最终组包，不为圆圈重新编译提示词、读文件、回忆记忆或调用模型。
- 完成观测保留上游输入；最终答案接纳后，基于实际保留的应用对话估算后续上下文。
- 有完整输入基准时，以“上游输入 + 保留对话估算变化量”校准，减少压缩后用全份 UI 历史高估的问题；仍不是 tokenizer 精确计量。
- 模型/来源/配置不匹配、无法证明来源或基准失效时回退明确标记的本地估算。
- failover 不套用原模型窗口；默认环境路线仅在实际首选路线相符且窗口已知时关联。
- 用户可见历史/工具配置改变后，显示用新鲜度 guard 作废旧基准。guard 缓存数值摘要，不复制正文，不是执行或安全权威。
- 观测随原有事件、宿主检查点、助手 modelContext 和历史水合保存。旧记录缺该字段时保持未知。

浏览器验收发现运行器会在最终文本接纳前清理 modelInvocation；初版因此丢失请求关联和输入校准。已保留经过 schema 校验的完成观测供最终保留估算使用，并补“请求句柄已清理”的回归。不延长句柄生命周期、不修改副作用重放语义。
