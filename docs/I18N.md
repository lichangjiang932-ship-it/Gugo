# i18n — 轻量国际化

最初 Stage 2.3 落地的最小骨架，现已覆盖**主要业务页面**与**5 种语言**。
不引大库，单文件翻译表 + 一个 React Context，整套实现 < 100 行（不含数据）。

## 支持的语言

| code | label | 角色 |
|---|---|---|
| `zh` | 中文 | **默认 + fallback 兜底** |
| `en` | English | 主要翻译 |
| `ja` | 日本語 | 全 key 对称 |
| `ko` | 한국어 | 全 key 对称 |
| `zh-TW` | 繁體中文 | 全 key 对称 |

测试 (`tests/i18n.test.js`) 强制 `ja / ko / zh-TW` 的叶子 key 集合与 `zh` **完全一致**——缺 key 或多 key 都 fail。`en` 与 `zh` 也强制一一对应。

## 架构

```
src/i18n/
├── translations.js     纯数据 + 纯函数 (translateKey / lookup)
└── I18nProvider.jsx    React Context + useT() hook
```

- 单一 `<I18nProvider>` 包在 `src/App.jsx` 最外层。
- 组件用 `useT()` 拿 `{ t, lang, setLang, languages }`。
- `t('nav.home')` 查当前语言 → 缺则 fallback 到 `zh` → 仍缺返回 **key 末尾段**（永远不崩、永远不会渲染 `key.not.found` 字面）。
- `useT()` 在没包 Provider 时也不崩：退化到纯 `zh`。
- 语言偏好写 `localStorage.lang`；跨标签页 `storage` 事件自动同步（v1 已实现）。

## 插值

`t(key, vars)` 支持 `{name}` 占位：

```js
t('slash.title.done', { title: 'My Session' })
// → "已将标题改为：My Session"
```

实现：单 pass `/\{(\w+)\}/g` 替换，未提供变量原样保留 `{name}` 便于排查。

## 为什么不用 react-i18next

| 维度 | 自建 (~100 行) | react-i18next |
|---|---|---|
| 体积 | 0 KB（直接打包） | +~40 KB gzipped |
| API 心智 | 一个 hook `useT()` | i18n 实例 / namespace / suspense |
| 插值 | `{var}` 单 pass，足够当前用 | ICU + 复数 + 格式化 |
| 复数 / 日期 | 暂不支持（v1 不需要） | 支持，但代价是体积 |
| 失败兜底 | 自己写，行为可控 | 默认行为不一定符合我们 |

当前 UI 文案规模 + 5 语言，自建够用。复数/区域日期等场景出现后再评估迁移。

## key 命名规范

```
<domain>.<key>
<domain>.<group>.<key>          # 二级允许（如 slash.archive.description）
```

- `domain` 限定枚举（当前 12 个，见下文）。
- 命名用 camelCase 单词（`emptyTitle`、`searchPlaceholder`），不要拼音、不要长句子做 key。
- 含变量的文案用 `{var}` 占位，调用方走 `t(key, { var: '…' })`。

## 加新 key 的流程

1. 打开 `src/i18n/translations.js`，**同时**在 `zh / en / ja / ko / zh-TW` 五种语言对应 domain 下加 key。
2. 跑 `npm test`：`tests/i18n.test.js` 会校验：
   - `zh / en` 全量叶子 key 一一对应（缺一个就 fail）
   - `ja / ko / zh-TW` 与 `zh` 全量对称
   - `nav / settings / errors` 各 domain 的最小 key 数量门槛（5 / 8 / 5）
3. 在组件里 `useT()` 拿 `t`，`{t('domain.newKey')}` 即可。

```jsx
import { useT } from '../i18n/I18nProvider.jsx'

function Foo() {
  const { t, lang, setLang, languages } = useT()
  return (
    <>
      <h1>{t('nav.settings')}</h1>
      <select value={lang} onChange={(e) => setLang(e.target.value)}>
        {languages.map((l) => <option key={l.code} value={l.code}>{l.label}</option>)}
      </select>
    </>
  )
}
```

## fallback 行为（约束）

`translateKey(key, lang)` 的失败链：

```
translations[lang][...key段] 命中 → 返回
  ↓ 缺
translations[zh][...key段] 命中 → 返回
  ↓ 仍缺
返回 key 的最后一段（"nav.notARealKey" → "notARealKey"）
```

**永远不抛错、永远不返回 `undefined` / `null` / 空字符串。**

未识别的 `lang` 代码（如 `fr`）同样走 `zh` fallback。

## 跨标签页同步

`I18nProvider` 注册 `window.storage` 监听：
当其它标签页写入 `localStorage.lang`，本标签页自动 `setLangState(newValue)` 同步。
只接受 `SUPPORTED_LANGUAGES` 白名单内的值，防止脏数据。

## 覆盖范围（当前）

**已接入 i18n** —— `useT()` + `t('domain.key')`：

- 导航：`LeftRail` / `SettingsView` / `NotificationCenter` / `Toast` / `SlashAutocomplete` / `SessionSearchModal`
- 业务页：`AgentList` / `CronJobsPage` / `ChannelsPage` / `SkillsMarket` / `TaskRunPanel` / `ChatSplit/CodingWorkbench` / `ChatSplit/index`

**尚未接入** —— Settings 二级页内部细节、部分老 Chat 子组件。缺 key 时 UI 仍渲染原中文（fallback 行为保证不崩）。

## 未来扩展

- **复数**：参考 ICU MessageFormat。如果只有 zh/en，简单两形态 `{ one: '...', other: '...' }` 即可。
- **日期/数字**：用原生 `Intl.DateTimeFormat` / `Intl.NumberFormat`，绑当前 `lang`。
- **服务端文案**：把 `translations.js` 抽到 `shared/` 让 server 也能查（错误码本地化）。
- **区域化降级**：如 `zh-HK → zh-TW → zh` 的链式 fallback（当前 `zh-TW` 是独立顶级语言，未做降级）。
- **真到 50+ 语言或需复杂插值时再上 react-i18next**。
