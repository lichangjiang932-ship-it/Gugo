# i18n v1 — 轻量国际化骨架

Stage 2.3 落地的最小 i18n 系统，覆盖**左侧导航**、**设置页**、**常见错误提示**三块。
不引大库，约 100 行实现。

## 架构

```
src/i18n/
├── translations.js     纯数据 + 纯函数 (translateKey / lookup)
└── I18nProvider.jsx    React Context + useT() hook
```

- 单一 Provider 包在 `src/App.jsx` 最外层。
- 所有组件用 `useT()` 拿 `{ t, lang, setLang, languages }`。
- `t('nav.home')` 查当前语言 → 缺则 fallback 到 `zh` → 还缺返回 key 末尾段（**永远不崩、永远不渲染 `key.not.found`**）。
- 语言偏好写 `localStorage.lang`；跨标签页 `storage` 事件同步。

## 为什么不用 react-i18next

| 维度         | 自建 (~100 行)               | react-i18next                  |
| ------------ | ----------------------------- | ------------------------------ |
| 体积         | 0 KB（直接打包）              | +~40 KB gzipped                |
| API 心智     | 一个 hook `useT()`            | i18n 实例 / namespace / suspense |
| 复数 / 日期  | 暂不支持（v1 不需要）         | 支持，但代价是体积             |
| 学习成本     | 5 分钟读完源码                | 文档 + 配置 + 插件系统         |
| 失败兜底     | 自己写，行为可控              | 默认行为不一定符合我们        |

当前 UI 文案少、语言少（zh/en），v1 自建够用。复数/日期/区域化等场景出现后再评估迁移。

## key 命名规范

```
<domain>.<name>
```

- `domain` 限定为：`nav` / `settings` / `errors` / `common`。
- 命名用 camelCase 单词（`emptyTitle`、`searchPlaceholder`），不要拼音、不要长句子做 key。
- 文案要换行/插值的，未来再加 `${var}` 占位约定（v1 暂不支持，直接拼字符串）。

## 加新 key 的流程

1. 打开 `src/i18n/translations.js`，**同时**在 `zh` 和 `en` 对应 domain 下加 key。
2. `npm test` —— `tests/i18n.test.js` 会校验：
   - zh / en 全量叶子 key 一一对应（缺一个就 fail）。
   - 各 domain 数量门槛（nav ≥5、settings ≥8、errors ≥5）。
3. 在组件里 `useT()` 拿 `t`，`{t('domain.newKey')}` 即可。

## 在组件里用

```jsx
import { useT } from '../i18n/I18nProvider.jsx'

function Foo() {
  const { t, lang, setLang, languages } = useT()
  return (
    <>
      <h1>{t('nav.settings')}</h1>
      <select value={lang} onChange={(e) => setLang(e.target.value)}>
        {languages.map((l) => <option key={l.code} value={l.code}>{l.label}</option>)}
      </select>
    </>
  )
}
```

## 覆盖范围（v1）

- `src/components/LeftRail.jsx` —— 整个左侧导航 + 搜索 + 会话分组 + 空状态。
- `src/pages/SettingsView.jsx` —— 设置二级 nav 标签 + 顶部**语言切换器**。其他设置页内部细节文案（系统诊断详情等）暂未翻译；缺 key 时 UI 仍显原中文。

老页面（Chat、Tasks、Skills 等）尚未接 i18n —— 由后续 stage 增量补；当前不会崩。

## 未来扩展

- **区域化**：`zh-CN` / `zh-TW` / `en-US` / `en-GB`。`SUPPORTED_LANGUAGES` 加项即可；`translateKey` 可加 region → base lang 的降级链。
- **复数**：参考 ICU MessageFormat。如果只有 zh/en，简单两形态 `{ one: '...', other: '...' }` 即可。
- **日期/数字**：用原生 `Intl.DateTimeFormat` / `Intl.NumberFormat`，绑当前 `lang`。
- **服务端文案**：把 translations.js 抽到 shared/ 让 server 也能查。
- **真到 50+ 语言再上 react-i18next**。
