# 模型配置、聊天目录与上下文圆圈修复

## 范围与保留项

按用户确认的四项计划实施：批量选择模型、保存后在聊天中可用、模型菜单添加入口、上下文进度。保留现有页面框架、侧边栏/本次改动/预览/任务清单、工具栏、暖纸语义与作品排版。已有未提交改动先外部快照；本批没有自动提交、推送或打包。

## 根因与修复

1. **候选不等于选中集合**。此前获取结果直接并入目录，要取消只能逐个移除。新 `ModelSelectionList` 供新增表单和已保存目录复用，全选/全不选/单项按钮有真实 `aria-pressed`；`enabled: false` 只取消聊天选用，不删除候选或窗口元数据。获取重复结果保留已取消项；默认按钮和明确删除操作仍独立。全不选真实保存，不回填预设。普通提供商编辑不再提交过期的目录快照，目录操作也不关闭正在编辑的卡片。
2. **配置写入与运行时不同步**。设置客户端 `/api/llm/*` 的成功变更现在通知已挂载聊天重读目录，失败不广播成功。运行时去掉必须显式设置 GUGO_HOME 才读取 YAML 的门槛，与写入端复用默认 home。测试环境单独隔离 HOME/USERPROFILE/GUGO_HOME，不能用生产读取门槛防止测试污染。禁用模型不进入允许目录，也不能通过指定 Provider 继续解析；同名模型的默认项保留 Provider 身份，部分编辑不会把 Anthropic 协议重置为 OpenAI。
3. **添加入口**。已可用模型列表增加固定的“添加模型”，在 listbox 外避免混成模型 option，空状态原配置入口保留。复用既有设置路由并回到原对话，保留草稿；移除按钮本身的重复令牌检查，设置路由的 RequireAuth 和后端认证均保留，不新增本机登录要求。
4. **窗口信息没有穿透**。原 SVG 本来就按百分比绘制，不应靠计时器或固定最小弧伪装修复。YAML 模型的 contextWindow、models.dev 缺省元数据和 `/models` 的有效窗口现在进入运行时模型画像，`getModelContextWindow` 也使用同一 per-model 信息。圆圈/详情仍复用已有当前待发送估算；不是历史累计用量，缓存命中也不从窗口扣除。没有可靠窗口时仍显示未知，不猜一个百分比。

## 测试与浏览器证据

- 新失败用例在修复前复现：候选批量/单项选择、成功通知、可用菜单缺入口、默认 home 读取、禁用模型、协议保留、默认 Provider 绑定及窗口传递。相关修复后通过。
- `ContextRingProgress` 使用真实 Composer/Hook 验证 0/25/70/99%、草稿增长、压缩回落、换模型/未知窗口；累计/缓存值不代替当前占用。
- `ModelConfigurationLiveCatalog` 将实际配置服务/运行时状态与挂载的配置页、聊天 Hook 连起来，验证取消后不重现，以及编辑保存不覆盖目录。异步按可观测 UI 条件等待，不用固定短 sleep 当成功证据。
- 隔离 Web：新建本机 fixture 提供商，实际 GET `/models` 获取 32 项，全不选后选 2 项，保存返回聊天无需重启即出现这两项；进一步操作已保存目录并收缩为 1 项，返回时草稿保持。
- 实际通过本机 HTTP 模型代理请求和正常输入框 Agent 流式发送；响应来自自己启动的本机确定性 fixture。正常输入框链路记录 1 次 stream 请求及 1 次非 stream 标题请求，模型均为选中的 fixture-model-17。没有真实 Provider、真实模型额度或待执行工具。
- 在真实输入框增加合成草稿，圆圈从 19.404% 增至 21.804%，再构造 70,000 / 100,000 tokens 的当前估算，实际 SVG 弧长比例 0.700；详情同为 70%。1440/360 × light/dark/white 共 6 组，无页面横向溢出。
- 初次浏览器夹具用了 10k 窗口，小于当时完整上下文估算，两次都已超过 100%，不能用来检验增长；改成明确的 100k fixture 后验证。另一脚本末尾直接 fetch 受保护状态接口被拒绝，改用生产认证客户端，不绕过认证。旧失败日志保留。
- 旧 ModelPicker 测试要求不存在 manage 按钮，DOM 对象与 null 的失败比较导致 Node 大量格式化并 OOM；更新为本次明确新增入口的行为断言，未扩大内存门槛或删可访问性检查。旧配置返回形状断言补齐新增 Provider/画像字段。
