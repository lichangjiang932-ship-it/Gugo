# 本机免登录桌面体验与内核可靠性收敛

日期：2026-10-14。基线 HEAD：`b5698be`，在上一轮未提交工作树上继续修改，未 reset、stash、commit、push 或发版。

## 1. 产品前提

- Gugo 是开源、免费、本地优先桌面应用。默认本机免登录，不新增注册、账户、套餐、积分或费用门槛。
- 本机身份由服务静默准备；内部 `userId` / `isLoggedIn` 等历史字段用于数据归属与连接状态，不代表用户必须完成账户登录。
- 本机连接失败或启动状态未知，只显示重连/恢复提示，不误弹多人登录窗口。
- 显式网络部署的身份隔离、回环监听边界、密钥保护、目录授权、审批与工具权限仍保留；没有把免登录改成公网匿名 Shell/文件接口。
- 手机/LAN 访问是显式启用入口后的访问钥匙配对，不是增加桌面账户登录要求，也不会自动开放监听地址。

## 3. A：可靠性与默认免登录

### 3.1 检查点保存产物策略计数

`server/services/loop/artifactFormatRejections.js` 增加版本化恢复与序列化：

- 策略拒绝记录进入 `completionGuards.artifactFormatRejections`，不再因进程恢复归零。
- 保留调用 ID，重复恢复同一已完成结果不重复消费拒绝次数。
- 计数饱和到既有策略上限，不新增更小调用/轮次预算。
- 旧检查点没有该字段时按空记录恢复；不支持的版本和无效结构拒绝继续，避免静默重置。
- 依然只针对请求中的生成器或实际修改债务对应路径；输入文档的只读格式警告不会触发输出熔断。

集成回归模拟第一次拒绝后中断，再用真实 Loop 恢复：写入只执行一次，累计两次拒绝后按原策略停止，已完成读取/写入不重放。

### 3.2 删除按操作隔离，失败可解释

- 删除等待状态由单个全局布尔值改为按会话记录，操作 token 防止过期结果修改新操作。
- A 的结果不会关闭 B 的确认框，也不会让 B 继承 A 的错误或等待状态。
- `dispatch(action, { onFailure })` 可接收归一化公开错误；旧调用的 `true/false/undefined` 返回契约保留。
- 活跃任务、版本冲突、记录不存在、访问不可用与未知结果有不同提示。
- 诊断 observer 抛错不能把失败操作变成成功或破坏队列。
- 结果未知只提示刷新核对，不宣布已删除/确定未删除，不自动重放请求。
- 等待窗口仍可收起，服务端操作不会被伪装成已取消。

### 3.3 本机连接与登录界面分离

- 只有明确的 `multi_user` 模式允许已有的多人登录入口显示。
- `local` / `unknown` 模式的连接故障不触发登录框。
- 受保护页面在本机身份未准备好时提供重连，不展示私有功能，也不把用户悄悄踢回聊天页。
- 启动状态未知时侧栏仍使用工作区语义，而不是伪账户语义。
- 关于/诊断页的邮箱登录配置仅限明确的多人部署，不混入本机默认体验。

## 4. B：缓存与公开输出诊断

### 4.1 样本覆盖率与缓存写入

新 `shared/modelUsageCoverage.js` 将读取与写入作为独立观测：

- 读取计数缺失、非法或无法形成有效分区时归为未知，不作为 0 命中。
- 显式上报的零保留为可用观测。
- 缓存写入单独汇总，未上报显示“未报告”。
- 用量报告提供整体、按模型、按会话的 `cacheCoverage`。
- 新 UI 使用有观测输入的加权命中率，显示“读取观测 / 已记录响应”。没有请求级观测时，不让旧汇总百分比冒充请求级测量。
- 只统计已持久化的 completed model phase，不把该数值称为所有物理尝试总数；UI 标签为“已记录响应”。截断和回合/模型明细不一致的既有提示保留。
- 切换时间范围立即移除上一范围的表格，同时作废旧请求版本；不在新范围按钮下短暂保留旧范围数字。

“可用观测”指上游报告且通过基本计数校验，不是本机独立证明了 Provider 的内部 KV 复用。

### 4.2 估算不再冒充计费与确定因果

- `missedCost` 缺费率时为 `null`，不再用 0 表示未知；混合有价/无价估算汇总也保留未知。
- 没有有效 TTL 或前缀证据时，miss 原因是 unknown。
- 只有明确传入有效 TTL 才提示 possible expiry，不跨 Provider 默认套五分钟。
- 原有 `CACHE_TTL_MS` 常量保留为明确知道 Anthropic short 策略的调用方参考值，不是通用推断。
- 重复输入量仍是基于计数重叠的启发式估算，不能证明相同字节、可缓存资格或账单事实。

**兼容说明：**报告新增 `cacheCoverage`；已有汇总字段保留供旧消费者使用。`cacheWaste.missedCost` 现在可能为 null，外部消费者不能再用 `Number(null)` 当真实 0 元。`describeCacheMiss()` 的无证据默认原因不再是 contentChanged/idleExpiry。

### 4.3 请求观测通过实际链路显示

输入框上下文弹层内增加默认折叠的请求观测：

- 现有应用/最终 wire 前缀与工具集合变化；首个不可比较请求明确显示无可比较样本。
- 实际发送工具数量，而不是拿候选工具估算冒充最终集合。
- 首个模型进展、首段公开输出以及二者间隔。
- 仅渲染计数、布尔状态和时间，不 stringify wire 数据。

时间与原有 fenced message action 一起进入 reducer，不额外提交第二次游标。重复/过期事件不重复记录首次公开输出。开始新的模型请求会清除旧请求的时间，不把上一次工具轮的说明误认成本轮已开始公开输出。

等待文案可以区分“已经收到模型进展”和“已经接收公开文字”。私有推理不显示；完成证据门控和安全说明缓冲未放开。

**观测边界：**时间来自宿主事件，不是浏览器实际首帧，也不是 Provider 内部首 Token。进展到公开输出的间隔可能包含继续生成、校验、传输与宿主发布，不能全部归因于缓冲。前缀比较沿用现有轮内诊断；没有逐请求本机编译归因时明确显示“无逐请求读数”，没有伪造第三层命中率。

## 5. C：桌面体验与性能

### 5.1 侧栏

- 标题最多两行，完整 tooltip、置顶和精确时间保持；不靠进一步缩小字号换空间。
- 同名项目显示路径辅助区分。
- 项目和会话显式分批展开，旧的活跃会话/项目仍可显示，避免搜索打开后选中项消失。
- 折叠项目不构造隐藏的会话行树，仍保留 disclosure 对应的控制区域。
- 默认本机模式可以看到保存的空项目和当前草稿项目；legacy 本机项目存储不会成为多人目录或授权凭据。
- 工作区菜单增加历史入口，菜单高度受视口限制。

2000 会话的组件回归验证初始行树上限和显式展开，不以“查不到旧会话”来换性能。

### 5.2 共用操作控件

增加 `src/components/ui/ActionButton.jsx`：原生 button、默认非提交类型、明确 busy/disabled、统一尺寸/语义颜色、减少动画和触屏最小高度。迁移本轮涉及的删除、重连、用量操作和列表展开控件。

这是存量 UI 的渐进基础，不声称数百个旧控件已经全部迁移。既有字体、主题、按下态和焦点反馈保持，不引入在线字体或重型新 UI 框架。

### 5.3 流式重算

- 历史 `MessageRow` memo，当前答案更新不必重新读取未变化的旧消息。
- React 状态路径使用 `createContextUsageEstimator()`，弱引用缓存不变消息和工具数组的数字估算，不保留额外正文副本。
- 保留未缓存的纯估算 API，给任意可变调用方使用；缓存工厂要求不可变输入。
- 模型窗口、实测输入和最新流式消息变化仍重新计算正确结果。

这只是客户端数字估算复用，不是 PromptCompiler 缓存，更不是上游模型 KV 命中。

### 5.4 离线基准

入口：`npm run benchmark:ui`。本机 Node v22.20.0 x64，2000 消息、60 工具、30 次流式更新，全部数字结果逐次与未缓存路径相同。

| 数字估算路径 | 中位数 | P95 |
|---|---:|---:|
| 未缓存 | 13.900 ms | 15.886 ms |
| 不可变快照复用 | 0.108 ms | 0.266 ms |

工作量：静态消息与 30 个新尾部消息合计计算 2029 次，工具估算一次、系统提示一次。结果受机器和负载影响，不能推广为应用整体提速比例或 UI 帧率。

### 6.2 浏览器与假模型闭环

使用独立临时 SQLite、工作目录和 Edge profile。`GUGO_LOAD_DOTENV=0`，模型请求只到自有 loopback 假模型，没有使用真实模型密钥、额度或会话。

验证：

- 本机首屏无注册/登录字段，恰好一个主地标。
- 假模型先提供活动，再由测试明确释放公开输出；页面显示进展，不暴露 `PRIVATE_OFFLINE_REASONING`。
- 诊断弹层有焦点与关闭回归；Esc 不会取消仍在进行的模型请求。
- 最终诊断来自实际 Gugo 请求/事件链，而不只是手工写入 UI 元数据。
- 48 个导入合成会话、同名项目路径、空项目、两行标题、历史入口与白/暗主题样式。
- 1024px 下聊天区至少 400px；640/390px 下右面板覆盖显示，聊天区分别保留 580/330px。
- 用量面板显示 1/1 读取观测和未上报写入。截图中 80% 是明确标记的假模型报告值，不是真实缓存基准。

## 7. 仍不应宣称已验证的事项

- 没有用真实 Provider 重跑复杂任务成功率；当前 starter live suite 仍是受控任务集，不能把离线通过数当任意真实工作的成功率。
- 本机编译缓存尚无逐请求归因，前缀观测不等于上游命中。
- 没有完整 Electron 安装包真机、BrowserView/原生选择器、长期内存和屏幕首帧基准；浏览器 UI 验证不能代替这些。
- host Shell 仍是明确的信任边界，不是 OS 沙箱；本轮没有自动要求所有 Windows 用户安装 Docker，也未放宽权限。
- 没有重新打包、签名、上传或自动更新。现有安装包不会因源码修改自动变成新版本。
