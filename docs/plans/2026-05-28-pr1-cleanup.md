## Task 5: 加 secret-redaction commit hook

**Why:** PROGRESS.md "已知问题" 自述：
> secret-redaction 工具会误改字面量。v0.5 把 `STORAGE_KEY = 'yma:activeAgentId'` 替成 `'***'`，跨 tab 全用户串台。教训：commit hook 前加 `git diff | grep "= '\*\*\*'"` 一道扫描（hook 还没加）

补这个 hook。

**Step 1:** 建 `.githooks/pre-commit`

```bash
#!/usr/bin/env bash
# 防 secret-redaction 工具误改字面量
# 触发条件：staged diff 含 `= '***'` 或 `= "***"` 形态赋值
set -e

if git diff --cached --unified=0 | grep -E "^\+.*=\s*['\"]\\*\\*\\*['\"]" > /dev/null; then
  echo "❌ pre-commit: detected '= ***' assignment in staged diff."
  echo "   secret-redaction tool likely overwrote a literal. Review:"
  git diff --cached --unified=0 | grep -nE "^\+.*=\s*['\"]\\*\\*\\*['\"]"
  echo
  echo "If intentional, bypass with: git commit --no-verify"
  exit 1
fi

exit 0
```

`chmod +x .githooks/pre-commit`

**Step 2:** 在 README.md "贡献" 段或 CONTRIBUTING.md 加一行
```markdown
## Git hooks
本仓库自带 pre-commit hook（防 secret-redaction 误改字面量）。clone 后跑一次：
\`\`\`bash
git config core.hooksPath .githooks
\`\`\`
```

**Step 3:** lint + test + commit
```bash
npm run lint && npm test
git add .githooks/ CONTRIBUTING.md README.md
git commit -m "chore: add pre-commit hook guarding against secret-redaction misfire"
```

## Pitfalls / 注意事项

- `git mv` 必须用，**不要** `mv` + `git add` —— 会断 history
- 改 PROGRESS.md 时**只动待办勾选状态**，不要重写整个文件结构
- pre-commit hook 用 bash 不用 sh（macOS sh 是 POSIX，不支持 `[[ ]]`）
- 加 hook 后跑 `git config core.hooksPath .githooks` 让本地生效；CI 跑不到无所谓
- `npm test` 在 Linux 第一次跑会 build better-sqlite3 native，需要 60-180s，耐心等
