## 二、判断错过又纠正的地方（最该读的一节）

这一节比上面那张表重要。下面每一条我都**先得出过错误结论**，然后被证据推翻。

1. **"这个端点不发 `cache_control`，所以缓存对你不生效"** —— 错。
   实测一个月真实流量：`mimo-v2.6-flash` 提示词有 **84%** 是缓存读，`mimo-v2.5` **67%**。
   端点自己做自动前缀缓存并上报 `cacheHitTokens`（从不上报 `cacheCreationTokens`）。
   前提对，推论错。**做任何缓存相关判断前先读 `<repo>/server-data/app.db` 里 `model.phase` 的 `usage`**。

2. **"读者 18 秒里什么都看不到"** —— 错。
   `ActivityStream` 从 turn 被接受起就渲染状态行（spinner + 计时器 + 按相位变的文案）。
   真正的问题是**最长那段窗口里的那句话说了不实的话**：模型从推理转到写正文时，
   正文被闸门扣着不发、心跳又只在相位变化时才 emit，客户端收不到任何事件，
   于是状态行一直停在"模型正在思考"。

3. **"那次有 3 次策略拒绝"** —— 错，是 **2 次**。我把 `turn.blocked` 那条也算进去了。
   教训：数 `tool.completed`，别数"提到这个字符串的事件"。

4. **我写了一条空过的测试。** 造"连败熔断"夹具时我按模块默认的 `maxConsecutiveErrors: 6`
   放了 6 次失败 —— 但循环实际装的是 **20**（`runtime-initializeSteering.js:490`）。
   那 6 次根本没熔断，测试**有没有被测行为都会通过**。是另一条测试失败才暴露的。
   **教训：夹具要按调用方实际传的参数造，不是按模块默认值。**

## 三、看起来像 bug 但**不是**的（别再去"修"）

### 1. 两次 `explicit_read_only_constraint` 失败（`6e176c78`、`88e261e4`）

读者明说"**只读，不要改动任何文件**"/"**只读操作**"，模型却分别调了 `create_docx` 和
`run_command`。护栏拒绝是**正确的**，而且拒绝文案本身就是给读者的指引。
我用真实字符串验过判定函数：它对这两个写请求正确返回 normal（没有粘住），对那几条只读请求返回 read-only。

唯一的摩擦点是 `run_command`：`node -e "console.log(2+2)"` 明明无害，但 shell 命令无法被证明只读，
所以一并拒绝。这是安全设计的代价，不是缺陷。

### 2. `runtime-completeToolBatch.js` 里"有成功就清空无进展判词"

我一度把它记成 latent bug 并写进了计划。**它是对的**，理由：

- `afterToolResult`（`server/utils/toolLoopGuard.js:191-196`）在**任何一次成功**时把
  `state.consecutiveErrors` 归零 —— 那处清空是在**跟守卫自己的计数器保持一致**。
- 留着一条守卫已经不同意的判词，会让"读确实回来了"的轮次被停掉。

**我是怎么证明的**：把整个分支 `else if (false && ...)` 掉，跑完整套件 ——
**1138 个文件全绿**。所以它当时**完全没被覆盖**，但那不等于它是错的。

**演示方法（这套方法在这个仓库里很好用）**：改动 → 拆掉被测代码 → 跑套件 →
红说明钉住了、绿说明是空过。这次会话我用它验过四处。

### 环境坑

- **代理会死。** `http.proxy` / `https.proxy` / `HTTP_PROXY` / `HTTPS_PROXY` 都指向
  `http://127.0.0.1:57417`。代理没起时 `git push` 报 `Failed to connect ... via 127.0.0.1`，
  这时直连也通常不通。**不要改配置**，用一次性绕过：
  `git -c http.proxy= -c https.proxy= push origin main`（代理在跑时就直接推）。
- **`<repo>/server-data/app.db` 的 schema_version 会污染树状态二分。** 库比代码新时打开会
  `DB_SCHEMA_VERSION_UNSUPPORTED`，让"回退代码"看起来挂了更多。~~每次换配置先 `rm -rf server-data/`。~~ **此建议已撤回，严禁用于真实数据目录。**
  换代码或配置做二分时，应新建隔离 `APP_DATA_DIR` / `APP_DB_PATH`，或使用已备份的匹配版本副本。
- **`.jsx` 测试不能直接 `node --test`**（`ERR_UNKNOWN_FILE_EXTENSION`），要用
  `node scripts/run-tests.js <路径>`。
- **收尾时别用会丢未提交改动的命令。** 这个会话里 `git stash` 过一次并成功 pop 回来，
  但代价很长——要收起 53 个文件时，先想清楚有没有更安全的路。
