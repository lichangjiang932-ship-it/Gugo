## PDF 验证契约

`pdf_text` 原有读取能力继续保留。指定 `verifyLayout` 时，必须提供
`expectedText`；可指定 `source`、目标 `pages`、`sectionLabel`、
`rectangles` 和 `previews`。所声明的检查由宿主执行，失败返回
`PDF_LAYOUT_VERIFICATION_FAILED`。回执列出实际检查，不能将它描述为
所有自由文本要求均已由机器证明。

回执签名的 authority 仅存在于当前服务进程，不写入文件或环境，
shell/worker 无法继承。相同进程的 JSON checkpoint 能核验签名；
冷进程或遗留布尔型“已验证”状态需要新的只读宿主验证。
审批、目录授权、取消和未知副作用的恢复边界继续适用。

原有 PDF 流程 fixture 改为真实 PDF 解析/宿主验收，保留行为断言。
专门的反向测试验证：只打印标记、伪造回执、改写回执、错误用户/Turn、
缺失文本、改动非目标页、越界、过期预览和未授权路径均不能获证。
